# CREATIVE_EDITOR_ANATOMY_AND_LAYERS_V1

The `Elementos` inspection panel has been structurally segmented to definitively uncouple the presentation of Semantic Identity (Anatomy) from Visual Rendering (Z-order/Paint Priority). This resolves confusion generated by forcing elements to express both their logical group and render position in a single collapsible hierarchy loop without adding any new architectural primitives.

## Structural UI Split (Template Mode)

The Elementos panel now houses two distinct active tabs:
1. **[ Anatomia ]** 
   - A *Semantics-First* projection.
   - Extracts read-only structural configurations defined directly in the Layout Registry (`resolveLayoutSections`). 
   - Uses collapsible visual blocks grouping common items (Ex: *Cabeçalho*, *Nota Editorial*). Section collapse operates as a transient UI operation, leaving authoring states untouched.
   - Elements are ordered topologically by layout definition, never reflecting dynamic user drag interactions.
   - Distinct inclusion of `Elementos Adicionados` below Anatomy explicitly separates Free Add-ons from strict layout structure without interlacing them.

2. **[ Camadas ]**
   - A *Paint Order / Operations-First* projection.
   - Presents elements iteratively scaled Back-to-Front.
   - Utilizes `ElementLayers`, offering deterministic drag capabilities via structural `onReorder` loops modifying `stackOrder`.
   - Divides Template assets distinctly against layered Free overloads via the **Sobreposição** UI boundary.
   - Reordering operations within this panel completely isolate themselves from the logic generating Identity paths in `Anatomia`. Anatomy != Paint Order.

## Free Composition Mode
For layouts running completely free variables:
- The system bypasses `TemplateElementsTab` entirely.
- Immediately focuses heavily on the raw Element addition surface + layer array manipulation using natively instantiated `FreeSceneElements`.
- No empty/faked Template tree is presented to the user.

## Scroll-To-Selection Parity
Syncing Selection state maintains cross-tab identity without losing focus.
- Custom element clicks (or template Canvas hit tests) assign values natively to `selectedTarget`.
- Both `Anatomia` and `Camadas` render distinct data-rows bearing target identifiers `data-layer-id={ID}`.
- To prevent hidden overflow targeting conflicts under Radix `TabsContent` configurations, the active document DOM resolver searches strictly for `[data-state="active"] [data-layer-id={ID}]`. Parity between UI and Canvas executes scrolling natively inside its container safely.
